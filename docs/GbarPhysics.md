# Gbar 定点物理：动量池与冲量残差

定稿方案：**动量池 + 冲量残差反馈**。所有改变速度的途径收拢为一个入口——`Impulse` 组件，`Velocity` 只由积分器写。

## 组件

```csharp
/// 质量，定点 kg（1:100，精度 0.01 kg）。
/// 没有此组件的实体不参与动量积分（着地角色等由玩法系统直接写速度）。
/// 天体不挂此组件，由 OrbitalSystem 走开普勒轨道推进。
public struct Mass
{
    public long Value;
}

/// 未消耗的动量池（定点 kg·m/s，1:100），向量方向相对于实体当前坐标域。
/// 受力系统只做加法写入，积分器兑换成速度后，未凑够一个速度量子的部分留在池中。
public struct Impulse
{
    public long X;
    public long Y;
    public long Z;
}
```

注意 `Impulse` 的语义是**动量（冲量），不是力**：

- 持续力（引力/推力/阻力）：产生系统每 tick 加 `F / tickRate`
- 一次性事件（爆炸/碰撞）：直接加一次完整冲量 J，时机不敏感
- 池中残留：已交付但还没兑换成速度量子的动量"零钱"

## 量纲与兑换公式

| 量 | 存储 | 缩放 | 最小刻度 |
|---|---|---|---|
| 位置 | `long`，单位 cm | 1:100 | 1 cm |
| 速度 | `long`，单位 cm/tick | 1:100 | 0.01 cm/tick ≈ 0.002 m/s（**量子**） |
| 质量 | `long`，单位 kg | 1:100 | 0.01 kg |
| 动量 | `long`，单位 kg·m/s | 1:100 | 0.01 N·s |

物理关系 `Δv = p / m`，定点展开（1 单位/tick = 0.2 m/s，故 `v_fix = v_si × 500`）：

```
Δv_fix = p_fix × K / m_fix        K = Scale² / tickRate = 10000 / 20 = 500
```

积分器每 tick 对每个分量执行：

```csharp
var dv = (long)((Int128)impulse.X * K / mass.Value);   // 截断，能换几格换几格
vel.X += dv;                                            // 入账速度
impulse.X -= (long)((Int128)dv * mass.Value / K);      // 只扣已兑换部分，残差留池
```

要点：

1. **Int128 必需**：`p_fix × 500` 溢出 long
2. **截断除法**：C# 整数除法向零截断，残差与池同号，正负方向对称
3. **兑换阈值**：`p ≥ m / 500`（SI 单位）才能换出 1 个量子。1000 kg 船 = 2 N·s

## 冲量残差机制

### 问题：亚量子的力会蒸发

速度只能整量子增减。若积分后清零池子，任何 `Δv < 1 量子` 的冲量每 tick 被截断成 0 且**不累积**：

- 1000 kg 船 + 2 N 离子推力：每 tick 交付 0.1 N·s，永远凑不到 2 N·s，飞船永远不动
- 1 AU 处太阳引力 ≈ 0.006 m/s²，低于每 tick 量子对应的 0.04 m/s²，深空无法入轨

### 解法：找零机制

积分后**不清零**，只扣掉已兑换的整量子部分，残差留在池中与后续冲量合并凑整。守恒律逐 bit 成立：

```
Σ 加入的冲量 = Σ (换出的速度 × 质量) + 池中残差
```

残差上界 < 1 个量子，永不丢失、永不超发。

### 例 1：离子船持续点火（1000 kg，2 N）

| tick | 加入 | 池中 | 兑换 | 残差 | 速度累计 |
|---|---|---|---|---|---|
| 1–19 | 0.1 N·s/次 | 攒至 1.9 | 0 | 全部留下 | 0 |
| 20 | 0.1 | 2.0 | 1 格（=2.0 N·s） | 0 | +0.002 m/s |
| 每 20 tick | … | … | 1 格 | 0 | 递增 |

每秒整 1 格，加速度 0.002 m/s²，与解析解 `F/m` 完全一致。

### 例 2：爆炸（一次性 5 N·s 击中 1000 kg 船）

```
Δv_fix = 500 × 500 / 100000 = 2.5 → 截断 = 2
换出 2 格（4 N·s），残差 1 N·s 留池，等待与下次冲量凑整
```

### 例 3：停止与反向

- 推力停止：池中残灰 < 1 量子，永远兑换不出去，不再产生运动；惯性由 `Mass × Velocity` 持有，MoveSystem 整数加法滑行，物理管线零读写
- 反向力：向零截断保证负残差留池，与后续正向冲量自然对冲

### 为什么截断而非四舍五入

四舍五入会把 2.5 换成 3，池里 5 N·s 却换出 6 N·s 的速度，超发部分变成负残差靠后续"还债"。数学仍守恒，但残差在正负间振荡，不可单调推理。截断保证：**残差与池同号、上界一个量子、只进不出直到凑整**。

## 两个动量存放处（不要混淆）

| | 存在哪 | 无外力时 |
|---|---|---|
| 实体的动量 m·v | `Mass` + `Velocity` | 不动，惯性滑行零成本 |
| 待入账的冲量残差 | `Impulse` 池 | 是空的，积分器无东西可兑换 |

无引力无推力时没有任何系统写池，`Δv = 0`，速度恒定——牛顿第一定律在这套结构里是免费的。

## 系统管线（每 tick 固定顺序）

| Order | 系统 | 职责 |
|---|---|---|
| 10 | `GravitySystem` | 引力：往池加 `μ·m/d²/tickRate`（double 算 long 存） |
| 20 | `ThrustSystem` | 推力：读推进组件，往池加 `F/tickRate` |
| 30 | `DragSystem` | 阻力：大气内往池加 `-k·v·\|v\|/tickRate` |
| 40 | `ImpulseIntegrationSystem` | 唯一积分点：`Δv = p/m`，残差留池 |
| 50 | `MoveSystem` | 唯一移动点：`pos += v`，纯整数加法 |

规则：

1. **受力系统只准加 `Impulse`，谁都不准碰 `Velocity`**
2. 多力叠加是整数加法，满足交换结合律——求和顺序无关，跨机器逐 bit 确定
3. 产生冲量的系统查询要带 `[All<Impulse, Mass, ...Velocity>]`，避免往无积分子能力的实体写入永不消费的动量
4. 没有 `Mass` 的实体（着地角色、舱内乘员）由玩法系统直接写 `LocalVelocity`，物理实体与玩法实体靠组件有无自然分层
5. 天体挂 `BodyOrbit` 走开普勒轨道，不进本管线
6. 碰撞/爆炸不再直接改 `Velocity`，统一往池里加冲量

## 明确不做

- 旋转/力矩/惯性张量：飞船朝向是玩法层的事，需要姿态控制时再加
- 碰撞求解：碰撞检测是独立系统，本层只定义其输出形式（冲量入池）
- 浮点累加顺序问题：不存在——定点整数加法天然顺序无关
