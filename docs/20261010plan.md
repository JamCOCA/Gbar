## 一、同步字段方案：碰撞描述下发

**结论：同步裁剪过的碰撞描述组件，不同步 `PhysicsBody` 本体。**

### 1. 新增 `ColliderDesc` 同步组件

`PhysicsBody` 的字段分三类处理：

| 字段 | 性质 | 处理方式 |
|---|---|---|
| `Type` / `Mass` / `RotationLock` | 模拟参数 | 下发（客户端本地预测需要） |
| `Shape`（Box/Sphere/Capsule 参数） | 静态几何 | 下发，仅随 EntitySpawn 一次 |
| `Handle` | 服务器运行时句柄 | 绝不下发，客户端自行建体 |
| `MeshVertices` / `MeshIndices` | 大体量资产 | 不走同步协议，资产化（见 §2） |

```csharp
[SyncComponent]
public struct ColliderDesc
{
    public PhysicsBodyType Type;
    public ShapeKind Shape;     // Box / Sphere / Capsule
    public Vector3 Param;       // Box: 半尺寸；Sphere: x=半径；Capsule: x=半径 y=半柱长
    public float Mass;
    public RotationLock RotationLock;
}
```

要点：

- **成本近零**：静态数据只出现在 `EntitySpawn`（新实体进入 AOI）中，不进每 tick Delta。
- **不同体型的实现路径**：体型是组件数据而非类型枚举。未来体型变化（buff/装备）= 更新该组件，服务器 `PhysicsSystem` 重建刚体（惰性建体机制天然支持重建）。
- 客户端缺 `ColliderDesc` 时可按 EntityType 用默认胶囊兜底。

### 2. Mesh 形状资产化

`PhysicsShape.Mesh` 带裸数组，不进入同步组件。改为：

- 同步协议只传 `MeshAssetId`（uint）；
- 网格本体走资产通道（随客户端版本发布或清单下载，见 §二.2）；
- 两端用同一份资产数据各自建碰撞体。

## 二、初始化流程、地形传输与持久化

### 1. 握手流程扩展为四段

```
Hello → Auth → Welcome ─┬─→ WorldInit（地形参数/资产清单 + 静态物）
                        └─→ 客户端确认世界应用完毕 → Ack → 开始 Keyframe/Delta
```

落地方式：

- `ClientSession` 增加 `WorldLoaded` 状态；
- `NetSyncSystem` 现有的跳过条件（`PlayerEntity == Entity.Null`）扩展为 `!session.WorldLoaded`；
- 复用现有"对齐前只发 Keyframe"的状态机概念，世界初始化与基线对齐是同一套门。

### 2. 地形传输：三方案

| 方案 | 适用 | 评价 |
|---|---|---|
| **A. 确定性生成（推荐）** | 高度场/噪声地形 | 只传 `seed + 参数集`，两端各自生成；物理碰撞用同一份高度场。零传输成本，一致性 = 参数哈希校验 |
| **B. 资产清单 + 分块下载** | 手工制作地形 | 世界切 chunk，每块带 SHA-256；`WorldInit` 只传清单（chunk 列表 + 哈希 + 版本） |
| **C. 塞进 Keyframe** | — | 不推荐。大网格撑爆 Keyframe 且与 diff 基线纠缠 |

`FragmentAssembler` 留给小数据（玩家建筑修改等）回退通道，不扛基础地形。

### 3. 持久化三层

| 数据 | 方案 |
|---|---|
| 静态世界（地形/建筑） | 版本化世界资产，DB 只存当前世界版本号（匹配 G8lands 赛季轮换：整档替换） |
| 动态实体（掉落物/场景状态） | 快照式：每 N 分钟 + 关服时序列化 `(NetId, Type, Position, Rotation, 状态组件...)` 为 JSONB/blob |
| 玩家 | 断线保存 + 周期兜底：位姿、生命/CPC、背包；不存句柄 |

现有架构的契合点（无需改动设计，只需补实现）：

- `Handle` 均为运行时惰性创建 → 存档不含句柄，加载后 `PhysicsSystem` 自然重建；
- `EntityFactory` 是唯一装配入口 → 恢复实体 = 读存档按 Type 分发到 Factory 方法。

### 4. 服务器启动顺序

```
InitAsync（配置/DB） → LoadWorld（地形 + 静态实体，骨架源自现 App.Debug 占位）
→ RegisterSystems / StartNet → Start
```

世界加载完成前不监听端口。

## 三、ECS 架构的未来扩展方式

### 通用三原则

1. **状态 = `[SyncComponent]` 组件，行为 = System（服务器权威），交互意图 = Packet 请求/响应**——与现有 `MoveInputPacket → MoveInput → MoveInputSystem` 链路完全同构。
2. **会话型交互（对话/交易）= 玩家实体上的状态组件 + RPC 式包**：状态组件驱动系统行为，且天然支持断线恢复与存档（组件在实体上，快照层自动覆盖）。
3. **一次性事件（命中特效/拾取提示/任务完成）需要独立的 S→C 事件通道**，现状只有状态同步，需补（见 §四.1）。

### 各系统落点

| 系统 | 组件（数据） | 系统（行为） | 包（交互） |
|---|---|---|---|
| **战斗** | `Health`/`Cpc`（已有）；击退走现有 `ApplyImpulse` 命令 | `CombatSystem`：消费 `NarrowPhaseCallbacks` 产出的接触事件，结算伤害/击退 | 攻击意图包（目标/技能 ID）；命中表现走事件通道 |
| **物品** | 物品堆 = Entity：`ItemTag + ItemDefId + Count + OwnerRef`；地面掉落 = `Position + PhysicsBody`（已有）；`CooldownState` | `InventorySystem`（按 OwnerRef 查询）、`UseItemSystem`（效果 = ItemDef 静态表驱动，GbarItems.md 回蓝道具三选一即首个用例） | 拾取/使用/丢弃请求包；拾取 = 改 OwnerRef，服务器原子执行 |
| **交易** | `TradeState`（双方玩家实体各一：对方 NetId + 物品快照 + 确认位） | `TradeSystem`：状态机推进，非法状态直接拒绝（主循环串行 = 天然无竞态） | 请求/接受/放入/确认/取消包 |
| **NPC 对话** | `DialogueState`（NpcNetId + 当前节点）；对话树 = 静态资产不进同步 | `DialogueSystem`：校验节点合法性、推进状态 | 开始/选项/推进/结束包（RPC 式） |
| **任务** | `QuestLog`（激活任务集：QuestId + 进度计数/位掩码，压缩存储） | `QuestSystem`：订阅战斗/采集等事件写进度；赛季重置直接写组件 | 任务相关请求包；进度变化随组件同步 |
| **组队** | `TeamRef`（指向 Team 实体或 TeamId） | `TeamSystem`：邀请/离队/共享进度 | 邀请/响应/离队包；队友位置走现有 AOI 同步，跨 AOI 可加"强制可见名单" |

### 实体类型扩展

`EntityType` 枚举直接追加（Npc、ItemDrop、Corpse、Team 等）。G8lands 设定"怪物死亡不刷新"→ 死亡 = 变 `EntityType.Corpse`/容器实体，由生态量系统统一管控区域个体数。

## 四、其他需要处理的事项

按优先级排列：

1. **S→C 一次性事件通道**：`GameEventPacket`（Unreliable，带 tick 序号防过期事件应用）。战斗表现、拾取提示、任务完成广播都依赖它。
2. **认证 DB 同步阻塞主循环**（`NetServerSystem.OnAuth` 已有注释标记为临时方案）：改为异步后台执行 + 主线程回填队列。
3. **移动安全校验**：现有归一化只防斜向加速，需补速度上限校验、`TeleportRequest` 合法性检查（防加速/瞬移挂）。
4. **断线重连策略**：玩家实体短期保留（1–2 分钟）+ 重连恢复，或销毁重建。决定存档时机与体验，需尽早定调。
5. **NetId 分配器持久化**：重启后从存档恢复计数器，避免恢复实体时 NetId 冲突。
6. **心跳与超时**：假死连接踢出 + 未认证连接超时踢出。
7. **协议前向兼容**：客户端遇到未知组件 ID 需可跳过（读长度丢弃）；`SyncComponent` 需要时可显式固定 Id。
8. **包体防护**：单包大小上限、每连接分片并发数上限，防 FragmentAssembler 被滥用耗尽内存。
9. **AOI 参数验证**：`VisibilityRadiusCells = 10` 需按玩法实际调优；移动实体每 tick 重写 `AoiCell` 的成本随实体数线性增长，注意观测。
10. **测试基建**：协议编解码往返一致性单测、物理确定性测试、多客户端模拟集成测试。
11. **并行查询规范**：系统编写约定——并行查询内禁止 World 结构变更（统一走 CommandBuffer 回放），写入项目规范文档。
